Teste: render fiel à geometria real (rasterizado vs. path tracer)

Carrega um módulo de verdade do catálogo (mesma peça, mesmas fórmulas, mesmo motor de posicionamento do visualizador do portal) e desenha ele dos dois lados — a única diferença é o MOTOR de render. Isso isola exatamente o que a troca de motor compraria (sombra suave, luz indireta, reflexo físico), com uma geometria que corresponde ao que o cliente configuraria de verdade — não uma peça genérica de teste. Nada aqui toca no app real — é um teste solto, só HTML, lendo direto do mesmo banco (só leitura).

Como abrir (2026-08-03: duplo-clique passou a funcionar) A página agora funciona abrindo o arquivo direto com duplo-clique (file://) — todas as bibliotecas 3D viraram um único script clássico local (js/vendor/render-fiel-bundle.js), que o navegador não bloqueia. Só o carregamento de módulos do banco (Supabase) pode não funcionar offline — e nesse caso a página renderiza sozinha o módulo manual de cozinha, sem banco.
O que é fiel e o que é simplificado aqui Fiel: dimensões de cada peça (mesmas fórmulas via js/pricing.js sem alteração), posição de cada peça dentro do módulo (laterais/topo/base/fundo/prateleira/porta/gaveta/pé/peça livre — porta lógica de placePieceInBox do viewer3d.js portada aqui), recursão de módulo-como-peça (gaveta com composição própria, modelo de porta etc.), cor real escolhida (swatch_hex).
Simplificado (não portado, pra manter este teste enxuto): textura de imagem nas cores (usa só a cor sólida), giro de canto (rotation_y_deg), inclinação de prateleira (tilt_angle_deg), cabide tubular oval, ferragem de dobradiça/furação, animação de abrir porta/gaveta (sempre desenhado fechado).
